Rearranging formulas: interaction specification

A learner must isolate a variable, keep a multi-term expression grouped, and identify when division is allowed. The design makes those decisions visible through targeted feedback.

Storyboard available · Production planned to begin soon

Context
REM Algebra 1, Unit 1, Lesson 5. Derived from the accompanying print lesson.
Audience
Algebra 1 learners who can solve numeric equations and are beginning literal equations.
My contribution
Instructional sequence, screen and trigger specifications, quiz items, and feedback wording.

Storyboard excerpts and instructional diagrams. A playable Storyline build, published UI captures, and LMS test results are not yet included.

A learner decision and its feedback

The difficult step in y = mx + b is dividing the entire difference y − b by m. These are excerpts from the design specification.

Slide 07 · Worked example

y − b = mx

x = (y − b) / m

Restriction: m ≠ 0.

The numerator stays grouped while dividing both sides.

Quiz feedback · Grouping error

Targeted error: x = y − b / m.

Close — but that only divides b by m. The entire quantity y − b must be divided by m: x = (y − b) / m.

Specified feedback directs attention to the operation that changed the expression.

Why these interactions

  • Ask for a mathematical decisionThe quiz checks the rearranged formula and the required nonzero divisor. Completing a reveal sequence alone would only establish exposure to the explanation.
  • Make feedback specific to the errorGrouping, division, and inverse-operation errors receive different explanations. The message identifies the move to revisit.
  • Separate the example from the performance checkWorked examples introduce the routine; five quiz items require learners to apply it to another requested variable.

Inspect the storyboard

The existing source storyboard specifies 16 screens, a five-item quiz, result and retry behavior, and a written exit ticket.

16-slide architecture
  1. StaticTitle + goalWordmark, goal band: "isolate any variable — and say when it's allowed."
  2. StaticBig ideaA = lw ⟷ w = A/l: same fact, pointed at a different letter.
  3. InteractiveInverse ops recapFour click-to-reveal cards; Next stays disabled until all four flip.
  4. BuildThe methodFour moves: box the target · undo in reverse · keep groups together · check.
  5. Worked ex. 1A = lw → wArea diagram; one move; restriction l ≠ 0 earned on screen.
  6. Worked ex. 2d = rt → tRate–time diagram; identical structure — near transfer by design.
  7. Worked ex. 3y = mx + b → xReverse order + grouping; "NOT THIS" misconception strip on final build.
  8. InteractiveTry it: P = 2l + 2wWork on paper first; reveal bars unlock strictly in order.
  9. StaticQuiz introRules up front: one attempt, instant feedback, restrictions count.
  10. Quiz Q1A = lw for wDirect check of worked example 1.
  11. Quiz Q2d = rt for tOrder matters: d/r, not r/d.
  12. Quiz Q3y = mx + b for xGrouping-error distractor gets its own targeted feedback string.
  13. Quiz Q4P = 2l + 2w for wPer-choice feedback names each specific mistake.
  14. Quiz Q5V = ⅓Bh for hTransfer item: clear the fraction first, then divide.
  15. Results80% to passSuccess and retry layers; Review Quiz on both paths.
  16. Exit ticketC = 2πr for rModel answer locked until the learner types a response.
Interaction and evaluation specifications
  • Reveal cardsFour inverse-operation pairs have normal and revealed states. A planned navigation condition waits until all four have been visited.
  • AssessmentFive formula-rearranging questions; one attempt per item with immediate feedback. The result screen specifies an 80% threshold with review and retry.
  • Exit ticketA written response explains how to isolate r in C = 2πr. The planned submit control checks for a nonblank response; this does not establish response correctness.
  • Planned verificationBuild and test trigger conditions, feedback paths, retry/reset behavior, keyboard navigation, reading order, and zoom. Verify completion and score reporting separately in the target LMS.
