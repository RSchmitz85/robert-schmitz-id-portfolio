Curriculum systems design

Scalable Algebra 1 Curriculum Architecture

A 144-lesson Guided Notes course — student reconstruction pages paired with annotated teacher editions — designed assessment-first, produced through a rules-driven engine, and surrounded by five reusable practice systems.

Role: Curriculum architect & designer Evidence: Real Engagement with Mathematics (REM) Scale: 144 lessons · 10 units
  • Curriculum system
  • Storyline
  • Assessment
  • PD / adult learning
  • AI workflow

Overview

The core of this system is a Guided Notes course: 144 lessons across ten units. Every lesson ships twice — a student reconstruction page set the learner completes (predictions, vocabulary, every solve) and a teacher edition with each response already annotated in red.

One course spine governs everything — Conceptual → Visual → Procedural → Transfer — and each lesson runs the same six-phase rhythm, Activate → Model → Guide → Apply → Reflect → Extend. Around the core: five practice engines treated as instructional asset systems, all fed by a production engine that refuses to render a page until the lesson's metadata, models, and assets resolve.

Challenge

Algebra 1 programs accumulate disconnected one-off lessons, so teachers rebuild structure every week. The design problem: a scalable architecture — shared lesson phases, predictable asset types, and page systems that cut design friction without lowering mathematical rigor.

Audience

  • Secondary Algebra 1 teachers running a coherent unit sequence
  • Intervention settings that need structure without diluted rigor
  • Curriculum leads who need templates that travel across topics

My role

  • Course architecture: B.E.S.T. benchmark-cluster crosswalk, unit big ideas, per-unit misconception registry
  • Guided Notes reconstruction template + annotated teacher edition
  • Activate→Extend lesson spine and the practice-system templates
  • Production pipeline spec: metadata → asset resolution → renderers → teacher-key mode → publication gate
  • Student pages, teacher editions, and cover systems as exemplars

Constraints

  • Teachable in real class periods; print- and LMS-friendly
  • One professional visual system across every asset type
  • Templates must carry many topics without rewriting the pedagogy

Methodology — design order first, then an engine that enforces it

The order is Dick & Carey's: analyze the standard and the learner, write the measurable objective, design the assessment that proves it, then build the instruction. Concretely: a lesson's reconstruction blanks, readiness checks, and annotated teacher edition are specified before its hook and worked examples are authored.

The analysis layer is written down, not tribal knowledge. The architecture document crosswalks every unit to Florida B.E.S.T. clusters but organizes the course by big ideas; each unit carries a "why this unit exists" rationale, a misconception registry (move-and-change-sign, "equals means the answer comes next," checking the transformed equation), a visual-model fade plan, and cumulative mastery checks instead of one-and-done unit tests. Slope is developed from covariation before any formula is named.

  1. Lesson requestCourse, unit, lesson → one canonical ID
  2. MetadataStandards, objective, template family
  3. Scenes & graphsConcept models resolved from the primary concept
  4. AssetsAlias → priority → manifest, before any rendering
  5. RenderersGuided Notes + practice pages
  6. Teacher-key modeSame source — keys never re-authored
  7. Publication gateFail-closed validation before release

Three production rules do the heavy lifting: every required asset must resolve (a missing model is a blocking failure); the teacher edition is a renderer mode, so keys can never drift from student pages; and the gate is fail-closed — any failed check stops the run with a structured error report.

Design process

  1. Analyze the standard and the learner

    Crosswalk the unit to its benchmark cluster; write down the misconceptions it must defeat.

  2. Fix the objective, then the evidence

    The reconstruction blanks, readiness items, and teacher edition are specified before any instruction is authored.

  3. Author instruction into the spine

    Hook with a prediction, model on the unit's visual representation, fade support tier by tier across the six phases.

  4. Systematize production

    Engine formats, cover systems, page layouts, key patterns — a new topic inherits production quality, not ad hoc formatting.

  5. Gate, measure, revise

    Fail-closed publication gate before release; assessment and classroom evidence after it, feeding revision.

Design decisions

  • Reconstruction over transcription Pages the student completes — predict, name the move, solve, check, define — not notes to copy. The teacher edition is the completed reconstruction, making the evidence design visible on every page.
  • Phase-based architecture over topic silos Teachers learn one instructional rhythm; content authors fill the slots.
  • Practice formats as systems, not one-offs Each engine encodes a learning interaction — self-checking, visual verification, movement with accountability, misconception analysis, structured peer coaching — reusable across standards.
  • Extend as a first-class phase Designed enrichment inside the same architecture — early finishers never get busywork.

Learning principles applied

Gagné's events + Gradual Release

The hook gains attention, Quick Retrieval recalls prerequisites without touching the new idea, Model presents on the unit's representation, and Guide fades support in tiers until the learner performs alone.

Mayer's multimedia principles

One routine per sub-minute segment; page graphics are instructional models that carry the mathematics, not decoration.

UDL-minded options

Five engines offer varied means of engagement on the same objective; the Daily Core / Additional Practice split builds planned flexibility into every lesson.

ARCS + Quality Matters as lenses

Hooks open on concrete contexts with a prediction stake; QM serves as a review lens for online delivery — a standard of practice, not a claimed score.

Outcome & reflection

The architecture holds at scale: 144 lessons, every one a reconstruction set with an annotated teacher edition, produced through the same pipeline and gate. New topics inherit lesson phases, evidence patterns, and asset templates instead of starting blank.

The designer's question underneath: what must stay constant so quality scales? The answer was the evidence design and the spine — objectives and checks fixed before instruction, plus a pipeline that refuses to ship a lesson whose parts don't resolve.

Evidence for hiring review is the system design itself — not sales or download metrics.
