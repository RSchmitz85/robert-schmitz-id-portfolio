Methodology

Designed assessment-first. Built by an engine.

The order is Dick & Carey's: analyze the standard and its documented misconceptions, fix the objective, design the checks that prove it — then author instruction. The REM Engine enforces that same order in production: nothing renders until everything upstream resolves.

  1. Lesson requestCourse, unit, lesson → one canonical ID
  2. MetadataStandards, objective, template family
  3. Scenes & assetsModels and graphs must resolve first
  4. RenderersGuided Notes + practice pages
  5. Teacher-key modeSame source — keys never drift
  6. Publication gateFail-closed checks before release

Full methodology — course architecture, misconception registry, and the ADDIE map — in the curriculum case study.

The practice layer

Four engines around the Guided Notes core

Each engine encodes one learning interaction on the same six-phase lesson spine — and every student page ships with a worked teacher key.

Punchline Math

Solve → decode → reveal: every answer self-checks against the punchline.

Color By Number

Twenty numbered regions keyed to answers — the picture verifies the math.

Scavenger Hunt

Solve, move, match: wrong answers dead-end — the route is the feedback.

Error Analysis Detective

Find the flawed step, correct it, explain why — misconceptions as objects of study.
