The instructional design lead

144 Guided Notes lessons, designed assessment-first

Ten units, 144 lessons, and every lesson ships twice: a student reconstruction page set the learner completes — predictions, vocabulary, and every solve — and a teacher edition with each of those responses already written in.

The design order is Dick & Carey's, not a worksheet generator's: analyze the standard and its documented misconceptions, write the measurable objective, design the checks that prove it — the reconstruction blanks, readiness items, and annotated key — and only then author the hook, models, and fading practice tiers. The same order is enforced in production: the REM Engine will not render a page until everything upstream of it resolves, and the teacher edition is a renderer mode, so student pages and answer keys can never drift apart.

  1. Lesson requestCourse, unit, lesson → one canonical lesson ID
  2. MetadataStandards, objective, template family resolved from the course architecture
  3. Scenes & assetsConcept models, graphs, and every asset must resolve before rendering
  4. RenderersGuided Notes + practice pages built from the resolved plan
  5. Teacher-key modeAnnotated edition rendered from the same source, never re-authored
  6. Publication gateFail-closed checks on artifacts, keys, and student/teacher separation

The full methodology — course architecture, misconception registry, and the ADDIE map — is in the curriculum case study.

Reusable instructional asset systems

The practice layer: four engines around the core

Around the Guided Notes core sits a practice layer that runs on the same six-phase lesson spine — Activate through Extend — so teachers learn a single instructional rhythm while the mathematics changes. Each engine encodes a learning interaction: self-checking, visual reinforcement, movement with accountability, misconception analysis. And every student page ships with a worked teacher key — a facilitation document, not an answer list. A fifth engine — Rally Coach coached partner practice — is documented in the curriculum case study.

Punchline Math

Solve → decode → reveal the punchline. Every answer maps to a decoder chunk and a numbered ticket, so students self-check while showing work. Ships with a fully worked teacher key.

Color By Number

Twenty numbered regions keyed to answers — every crevice labeled, whole scene painted on the teacher key. Practice stays rigorous while the picture verifies the math.

Scavenger Hunt

Movement with accountability: solve at a station, follow your solution to the matching arrival signal, close the loop. Wrong answers dead-end — the route itself is the feedback.

Error Analysis Detective

Mistakes as objects of study — students find the flawed step, correct it, and explain why. Diagnostic noticing built into a repeatable casebook template.

Static pages show the artifacts; the walkthrough shows the interaction design — how an answer becomes feedback, how the picture verifies the math, and what the teacher receives to run it.
